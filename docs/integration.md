# Загрузка прайса на сайте

## Поток данных

1. Оператор получает еженедельный XLS/XLSX и загружает его через форму сайта.
2. Backend передаёт файл в `BtdetalParser.import_price()`. Дата прайса не требуется.
3. Библиотека проверяет таблицу, отбрасывает нулевые остатки и атомарно заменяет
   содержимое локального файла SQLite вместе с поисковым индексом.
4. Поисковые запросы используют `search()`/`search_many()` и не читают Excel.

Доставка прайса из почты и сама форма загрузки остаются задачей сайта.
Библиотека предоставляет точку приёма файла и все операции с данными.

## Пример для FastAPI

FastAPI не является зависимостью библиотеки. Пример предназначен для
существующего backend с установленными FastAPI и python-multipart.
Обработчик загрузки нужно включить в существующую авторизованную панель оператора.

```python
from fastapi import File, HTTPException, UploadFile
from starlette.concurrency import run_in_threadpool
from btdetal import BtdetalParser, PriceImportError

prices = BtdetalParser("/var/lib/my-site/btdetal.sqlite3")


@app.post("/suppliers/btdetal/price")
async def upload_price(file: UploadFile = File(...)):
    try:
        return await run_in_threadpool(
            prices.import_price,
            file.file,
        )
    except (PriceImportError, ValueError) as exc:
        raise HTTPException(status_code=422, detail=str(exc)) from exc


@app.get("/suppliers/btdetal/search")
def search_price(q: str):
    return prices.search(q, max_results=10)
```

Excel — синхронная обработка, поэтому в асинхронном обработчике импорт
переносится в рабочий поток. Для больших файлов можно использовать очередь
фоновых заданий. Библиотека принимает до 50 МиБ; лимит HTTP-загрузки сайта
следует согласовать с ним. Файл читается с текущей позиции потока.

## Хранение

Используйте один постоянный абсолютный путь к базе для импорта и поиска,
доступный всем worker-процессам на одном сервере. Директория должна быть
доступна для записи процессу импорта и для служебных файлов SQLite WAL.
Не размещайте WAL-базу на сетевом файловом ресурсе. Для нескольких серверов
разместите библиотеку за одним backend API либо используйте отдельную
централизованную БД после изменения слоя хранения.

Одновременные импорты сериализуются SQLite; последним становится тот прайс,
чья транзакция завершилась последней. Дата прайса не проверяется и не сравнивается:
каждый успешно обработанный файл заменяет текущие данные независимо от даты.

Архив исходных файлов библиотека не ведёт. При необходимости сайт сохраняет
загруженный файл отдельно. Для резервного копирования работающей базы
используйте SQLite backup API, а не копирование только `.sqlite3` при открытом WAL.

Дополнительный Redis-кеш обычно не нужен. Если сайт кеширует результаты,
включайте `get_metadata()["sha256"]` в ключ кеша либо сбрасывайте кеш после импорта.
Дата и хеш должны читаться согласованно с собственной политикой кеширования:
при одновременном импорте отдельные вызовы API могут видеть разные версии.

## Проверки импорта

Обязательные колонки: `Код`, `Артикул`, `Номенклатура`, `Остаток`, `1-я цена`.
Их порядок не важен; заголовок ищется в первых 100 строках. При нескольких
подходящих листах требуется `sheet_name`. Дополнительные колонки игнорируются.
Заголовки разделов без кода и артикула с пустым/нулевым остатком пропускаются.
Отрицательные и неизвестные остатки отклоняются. У доступных товаров проверяются
код, название и неотрицательная цена; нулевая цена допустима и не подменяется.

Формулы не исполняются: используются сохранённые результаты Excel. Остаток
без сохранённого значения приводит к ошибке импорта. Пустая цена, в том числе
формула без сохранённого значения, остаётся null: товар возвращается с ошибкой
цены, а общий поиск — с partial_error. Счётчик missing_price_count показывает
количество таких позиций после импорта.
Строковые идентификаторы сохраняются. Числовые идентификаторы с форматом
`000...` дополняются нулями. Если Excel уже округлил длинное число из-за своего
ограничения точности, восстановить исходный артикул невозможно: такие артикулы
поставщик должен сохранять текстом.

Ошибки в товарных строках не скрываются: импорт отклоняется целиком с указанием
листа и строки. Результат успешного импорта содержит счётчики и SHA-256 файла.
